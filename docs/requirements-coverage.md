# 需求覆盖矩阵

| 题目要求 | 实现 | 验证 |
|---|---|---|
| 学生、教师、Registrar 登录 | `identity` 三角色 + BCrypt + 后端角色授权 | 模块 1 集成测试 |
| 管理员维护学生/教师完整档案 | `people` CRUD：姓名、出生日期、证件、状态、专业/院系、毕业日期 | 模块 2 测试与 People 页面 |
| 旧课程目录只读，不允许修改 | `catalog` 仅 GET，`/status` 明示 source/readOnly/10 秒预算 | 模块 3 测试 |
| 每名学生 4 主选 + 2 备选 | 提交前严格计数，类型内优先级唯一 | 模块 4 测试 |
| 课表创建、保存、修改、删除、提交 | `RegistrationService` 和完整页面操作 | 模块 4 测试 |
| 开放期内增删课 | 所有变更先检查 `RegistrationWindow.open` | 服务校验 |
| 先修课、开放状态、冲突、满员检查 | 提交时统一校验；教学班用悲观锁避免超卖 | 模块 4 测试 + 代码 |
| 满员时提示学生 | 错误包含具体课程“已满，请重新选择” | 异常响应 |
| 容量最多 10、最低 3 | 教学班默认 10/3；关闭时统计 | 模块 7 测试 |
| 教师选择/退选符合资格的课程 | 本院系、无人任教、开放窗口、无冲突 | 模块 5 测试 |
| 关闭后教师不得调整 | `requireOpenWindow` 双重检查窗口和教学班状态 | 模块 5 规则 |
| 教师查看本人教学班名单 | 所有权检查后由已 ENROLLED 记录生成 | 模块 5 页面 |
| A/B/C/D/F/I，空成绩允许 | 仅 CLOSED 教学班可录入；空值保留未录入 | 模块 6 测试 |
| 学生查看上学期成绩单 | 本人关联账号，显示学分、已获学分和 GPA | 模块 6 测试 |
| 关选课取消无教师班 | 第一阶段直接取消并释放学生记录 | 模块 7 测试 |
| 按优先级补入备选 | 主选不足 4 时逐项检查资格、容量、冲突 | `levelSchedule` |
| 少于 3 人取消 | 补位后再次计数，不足者取消 | 模块 7 测试 |
| 冻结最终课表并生成计费 | 仅 SUBMITTED 课表计费，草稿不计费 | 模块 7 测试 |
| 计费不可用时重试 | PENDING/FAILED/SENT、次数和最后尝试时间 | 失败→成功测试 |
| 安全与并发 | 后端 RBAC、本人/任课所有权、容量悲观锁 | 模块 1/4/5 测试 |

## 明确的课程环境适配

题目描述的真实旧式 Ingres/DEC VAX 和外部计费系统不在本机可用范围内。项目没有伪称已连接真实系统，而是分别用“只读目录适配器”和“可失败的计费状态机”保留接口边界、超时预算和重试语义。这是受控替代，不影响核心用例验收。
