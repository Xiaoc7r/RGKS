# 成员 7：关选课与计费

## 你负责什么

你负责选课期结束后的批处理：关闭选课窗口、取消无人任教教学班、按优先级尝试备选补位、取消不足 3 人课程、冻结课表、生成计费记录，并模拟外部计费失败后的重试。

这是全流程最后一个模块，现场一定最后演示。关选课一旦执行，学生和教师就不能继续调整。

## 固定处理顺序

1. 检查窗口仍为 OPEN，防止重复结算。
2. 取消没有教师的教学班。
3. 对 SUBMITTED 课表按备选优先级尝试补足到 4 门。
4. 重新统计人数，取消少于最低 3 人的教学班。
5. 只为已提交课表生成计费；草稿不收费。
6. 所有课表设为 FINALIZED，剩余教学班设为 CLOSED。
7. 关闭选课窗口。

顺序不能随意交换。例如先判断最低人数再补位，可能错误取消本来能通过备选达到 3 人的课程。

## 现场演示（90 秒）

1. 先确认学生已经提交 4+2 课表。
2. 用管理员进入“结算与计费”，展示窗口开放、教学班数和已提交课表数。
3. 点击“执行关选课”，确认操作。
4. 展示摘要：取消教学班、补位数、冻结课表和计费总额。
5. 在一条计费记录上点“模拟失败”，状态变 FAILED、次数加一。
6. 再点“重试成功”，状态变 SENT、次数再次加一。

## 核心代码块怎么讲

```java
int cancelledCount = cancelOfferingsWithoutProfessor(semesterOfferings);
for (StudentSchedule schedule : semesterSchedules) {
    if (schedule.getStatus() == ScheduleStatus.SUBMITTED) {
        promotedAlternates += levelSchedule(schedule);
    }
}
cancelledCount += cancelUnderEnrolledOfferings(semesterOfferings);
```

背法：先取消无教师班，再对正式提交课表补位，最后判断最低人数；三个阶段的顺序就是结算不变量。

```java
billing.setRetryCount(billing.getRetryCount() + 1);
billing.setLastAttemptAt(Instant.now());
billing.setStatus(success ? BillingStatus.SENT : BillingStatus.FAILED);
```

背法：每次调用外部计费都留下状态、次数和时间，失败不是直接丢弃，而是允许再次重试。

## 60 秒背诵稿

> 我负责关选课与计费模块。管理员关闭选课时，Service 在一个事务内按固定顺序处理：先取消无人任教班，再对已提交课表按优先级尝试备选补位，然后取消不足最低 3 人的教学班，最后冻结课表并按仍然有效的已录取课程汇总学费。草稿课表不会计费。完成后开放教学班变为 CLOSED，窗口关闭，避免继续修改。外部计费在课程环境中用状态机模拟，记录 PENDING、FAILED、SENT、重试次数和最后尝试时间，可以现场演示失败后恢复。

## 必背术语

- **批处理**：一次处理某学期全部教学班和课表。
- **业务不变量**：执行过程中必须始终遵守的规则，例如结算顺序。
- **备选补位**：主选不足 4 门时按 priority 从小到大尝试录取备选。
- **幂等保护**：窗口关闭后拒绝再次关选课，避免重复结算。
- **状态机**：计费在 PENDING、FAILED、SENT 状态间转换。
- **可观测性**：用重试次数和时间看见外部调用结果。

## 老师追问

**问：为什么草稿不计费？**

答：草稿不是学生正式提交的意愿，只有 SUBMITTED 课表才能冻结并收费。

**问：为什么计费不直接调用真实平台？**

答：课程环境没有外部平台，状态机模拟保留了请求成功、失败和重试语义，不伪造真实接口。

**问：关选课执行一半失败怎么办？**

答：方法有 `@Transactional`，数据库异常会整体回滚；窗口只有在最后成功时才关闭。

**问：备选一定能补进去吗？**

答：不一定。候选班必须开放、有教师、未满、无时间冲突，并满足先修课。

**问：为什么两名背景学生？**

答：课程最低人数是 3。演示库预置 2 人，student1 提交后四个主选班正好达到 3 人，既能展示正常开课，也保留两个无人教师班展示取消。

## 及格重点

必须按顺序背出“无教师取消 → 备选补位 → 低人数取消 → 冻结计费 → 关闭窗口”，再解释计费失败可重试。
