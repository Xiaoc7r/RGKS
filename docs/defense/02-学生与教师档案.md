# 成员 2：学生与教师档案

## 你负责什么

你负责注册管理员维护学生和教师基础资料，包括新增、查询、修改、删除、唯一编号检查、人员状态和身份证件脱敏。账号和人员档案是两种对象：账号用于登录，档案用于业务数据。

## 现场演示（60 秒）

1. 用 `registrar / Registrar123!` 登录，进入“人员档案”。
2. 新增一个测试学生，填写学号、姓名、出生日期、证件号、状态和毕业日期。
3. 指出列表只显示 `****0099`，不会返回完整证件号。
4. 把状态改为 `ON_LEAVE`，证件号留空并保存，说明留空表示保留原值。
5. 删除刚创建的测试学生。

## 核心代码块怎么讲

```java
if (students.existsByStudentNumberAndIdNot(request.studentNumber(), id)) {
    throw new IllegalArgumentException("学号已存在");
}
if (request.identityNumber() != null && !request.identityNumber().isBlank()) {
    student.setIdentityNumber(request.identityNumber().trim());
}
```

背法：修改时先排除当前记录再检查学号重复；证件号为空就不覆盖数据库原值，否则页面上的空框会把真实号码擦掉。

```java
if (accounts.existsByLinkedPersonIdAndRole(id, UserRole.STUDENT)) {
    throw new IllegalStateException("学生仍有关联登录账号，不能删除");
}
```

背法：删除档案前检查是否还有登录账号引用，防止产生“账号能登录但找不到人员”的悬空数据。

## 60 秒背诵稿

> 我负责学生与教师档案模块，入口角色是注册管理员。Controller 使用 DTO 接收参数，Service 负责学号或工号唯一性、必填证件号、状态更新和删除保护，Repository 负责数据库访问。学生与教师分别使用独立实体，因为学生有专业和毕业日期，教师有院系。证件号码属于敏感信息，数据库保存业务所需原值，但接口只返回后四位掩码。修改时证件框留空代表保留，避免把掩码写回数据库。若人员仍关联登录账号，系统拒绝删除，保证账号和档案引用一致。

## 必背术语

- **CRUD**：Create、Read、Update、Delete，增查改删。
- **唯一约束**：学号/工号不能重复，Service 和数据库共同保证。
- **DTO**：接口数据对象，不直接暴露 Entity。
- **脱敏**：隐藏敏感字段的大部分内容，只显示必要部分。
- **引用完整性**：被其他数据引用的记录不能随意删除。
- **事务**：修改和校验在一次数据库事务中完成。

## 老师追问

**问：为什么学生和教师不做成一个 Person 表？**

答：两者公共字段虽相似，但学生和教师有不同业务字段和生命周期。课程规模较小，分表更直观，也避免大量空字段。

**问：只在前端检查学号重复行不行？**

答：不行。并发请求或绕过前端都会失效，所以后端先查，数据库唯一约束最终兜底。

**问：为什么接口不返回完整身份证？**

答：页面只需要确认是否已填写和核对末四位，返回全文会扩大敏感信息暴露面。

**问：删除失败是不是 Bug？**

答：不是。有关联账号时拒绝删除是业务保护；应先处理账号关系，再删除档案。

## 及格重点

能说清“账号不等于人员档案”“唯一性检查”“证件脱敏”“有关联账号不能删”，就足够支撑本模块答辩。
