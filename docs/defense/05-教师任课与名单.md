# 成员 5：教师任课与名单

## 你负责什么

你负责教师在选课开放期选择或退选教学班，并查看本人教学班的学生名单。系统不是“只要是教师就能操作所有班”，而是先检查角色，再检查院系资格、任课所有权和时间冲突。

## 现场演示（60 秒）

1. 用 `professor1 / Professor123!` 登录，进入“任课与名单”。
2. 页面上半部分是“我的任课”，选择一门已有课程查看名单。
3. 下半部分只列出本院系、开放且无人任教或本人任教的教学班。
4. 选择 NET201，成功后它进入“我的任课”。
5. 再退选 NET201，说明窗口关闭后这两个动作都会被拒绝。

## 核心代码块怎么讲

```java
if (!professor.getDepartment().equals(course.getDepartment())) {
    throw new IllegalStateException("只能选择本院系开设的课程");
}
boolean conflict = offerings
    .findByProfessorIdAndSemesterOrderByDayOfWeekAscStartPeriodAsc(
        professor.getId(), target.getSemester())
    .stream()
    .filter(existing -> !existing.getId().equals(target.getId()))
    .anyMatch(target::conflictsWith);
```

背法：先检查教师院系与课程院系一致，再把目标教学班与该教师本学期所有任课比较；只要一天且节次区间重叠，就拒绝选择。

```java
if (!professorId.equals(offering.getProfessorId())) {
    throw new IllegalStateException("只能查看自己任教的课程");
}
```

背法：`PROFESSOR` 角色只是第一层，教学班所有权是第二层，防止教师查看其他教师的学生名单。

## 60 秒背诵稿

> 我负责教师任课与名单模块。教师登录后，系统从账号取得关联教师档案，只允许 ACTIVE 状态教师操作。可选教学班必须处于开放状态，课程院系与教师院系一致，而且不能已经被其他教师选择。选择前还会把目标时间与本人已有任课逐一比较，避免教师同一时间上两门课。查看名单和退选都要验证 professorId 所有权，不是只检查 PROFESSOR 角色。选课窗口关闭或教学班结束后，系统拒绝继续调整，保证最终课表稳定。

## 必背术语

- **资格过滤**：按院系、状态等条件筛选可操作对象。
- **资源所有权**：角色正确还不够，只能操作归属于自己的资源。
- **时间区间重叠**：同一天且 `start <= other.end && other.start <= end`。
- **双层授权**：角色授权 + 数据所有权授权。
- **Roster**：教学班学生名单。
- **开放窗口**：允许学生和教师调整选课相关数据的时间状态。

## 老师追问

**问：为什么“可选列表”里也有自己的课程？**

答：统一列表同时表达“符合资格”和“是否已经归我”，前端用 `ownedByMe` 禁用重复选择，用户能看清当前状态。

**问：两个教师同时选择同一个班怎么办？**

答：选择时使用 `findByIdForUpdate` 锁定教学班，再检查 professorId；后一个事务会看到已有教师并被拒绝。

**问：教师能看其他老师的名单吗？**

答：不能。Service 的 `requireOwnedOffering` 会校验当前 professorId。

**问：为什么成绩不放在这个模块？**

答：任课与名单发生在选课期，成绩发生在课程结束后，生命周期和规则不同；拆开后刚好形成独立答辩边界。

## 及格重点

讲清“本院系、无人任教、无时间冲突、只能看自己的班、关选课后不能改”即可。
