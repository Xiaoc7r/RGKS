# 成员 4：学生选课与课表

## 你负责什么

你负责业务规则最多的学生模块：学生建立课表草稿、选择 4 门主选和 2 门备选、调整优先级、保存或删除，并在提交时检查窗口、先修课、课程状态、时间冲突和容量。

## 三个状态要背熟

- 课表 `DRAFT`：草稿，可以继续修改，不占最终名额。
- 课表 `SUBMITTED`：已提交，四门主选状态变成 `ENROLLED` 并计入容量。
- 课表 `FINALIZED`：管理员关选课后冻结，不能再改。

选课项还有 `SELECTED / ENROLLED / CANCELLED`，分别表示候选、已录取、已取消。

## 现场演示（90 秒）

1. 用学生账号进入“学生选课”。
2. 主选依次加入 CS201、SE201、DB201、WEB201，优先级 1–4。
3. 备选加入 NET201、SE301，优先级 1–2。
4. 修改一条优先级并保存，指出状态仍为 DRAFT。
5. 点击“提交课表”，状态变为 SUBMITTED，主选项变为 ENROLLED。
6. 若要演示错误，可故意用重复优先级，系统会返回具体提示。

## 核心代码块怎么讲

```java
long primaryCount = allItems.stream()
    .filter(item -> item.getChoiceType() == ChoiceType.PRIMARY).count();
long alternateCount = allItems.stream()
    .filter(item -> item.getChoiceType() == ChoiceType.ALTERNATE).count();
if (primaryCount != 4 || alternateCount != 2) {
    throw new IllegalStateException("提交前必须选择 4 门主选课和 2 门备选课");
}
```

背法：可以随时保存不完整草稿，但提交是业务承诺，因此必须严格等于 4+2。

```java
CourseOffering offering = offerings.findByIdForUpdate(item.getOfferingId()).orElseThrow();
validateOffering(studentId, offering, selectedOfferings);
```

背法：提交时对教学班加数据库悲观写锁，再检查容量。两个学生同时抢最后一个名额时，后来的事务要等待前一个完成，避免超卖。

## 60 秒背诵稿

> 我负责学生选课与课表模块。学生先建立 DRAFT 草稿，可以增删课程、修改主备选类型和优先级。提交时系统要求严格 4 门主选和 2 门备选，然后逐门检查教学班开放状态、先修成绩、时间冲突和容量。容量检查前使用悲观锁锁定教学班，避免并发学生同时抢到最后一个名额。通过后四门主选变成 ENROLLED，课表变成 SUBMITTED；备选仍是 SELECTED，等待关选课时按优先级补位。已提交课表再次修改会回到 DRAFT 并释放占位，重新提交后才重新占容量。

## 必背术语

- **4+2 规则**：4 门主选、2 门备选。
- **草稿/提交分离**：草稿可不完整，提交必须满足全部规则。
- **悲观锁**：认为竞争可能发生，先锁数据再检查和修改。
- **容量超卖**：实际录取人数超过教学班容量。
- **先修校验**：要求历史成绩为 A/B/C/D 才算通过。
- **时间冲突**：同一天的节次区间发生重叠。

## 老师追问

**问：为什么加入草稿时不检查所有规则？**

答：草稿允许用户逐步安排；提交才是正式占位点，所以统一校验可以避免半完成数据占容量。

**问：为什么备选不立即 ENROLLED？**

答：备选只在主选因取消等原因不足 4 门时，由结算模块按优先级尝试补位。

**问：乐观锁不行吗？**

答：可以，但需要版本冲突后重试。课程项目用悲观锁逻辑更直观，且单个教学班竞争范围小。

**问：学生能修改别人的课表吗？**

答：接口不接收外部 studentId，而是从当前登录账号取得关联学生 ID，再按该 ID 查询课表。

## 及格重点

背熟“草稿不占位、提交检查 4+2、主选悲观锁、备选后补位”四句话即可。
