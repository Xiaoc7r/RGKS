# 七人答辩指南

建议总时长 12–15 分钟。每人 60–90 秒，统一使用“需求—设计—异常—验证”的四句结构。

## 开场（组长，30 秒）

“我们实现的是高校选课注册系统，采用 Vue 3、Spring Boot 和 MySQL 的模块化单体。没有为追求技术名词拆微服务，而是按 7 个业务边界让 7 名成员一人一模块；系统完成从登录、选课、任课、成绩到关选课和计费的闭环。”

## 成员 1：认证与权限

- 演示学生登录，再直接访问人员接口得到 403。
- 说明 BCrypt 只存密码哈希；Basic Auth 只作为本机课程演示。
- 追问：前端不显示按钮为什么还要后端鉴权？答：请求可绕过前端，安全边界必须在服务端。

## 成员 2：人员档案

- 新增学生、修改为 ON_LEAVE、删除。
- 强调学号/工号唯一，证件号响应只显示后四位。
- 追问：更新时为何证件号允许留空？答：页面看不到原文，留空表示保留，避免掩码覆盖真实值。

## 成员 3：课程目录

- 展示只读状态、先修课、学费、容量和剩余座位。
- 说明 Course 是课程定义，CourseOffering 是某学期具体教学班。
- 追问：为什么没有接真实 VAX？答：外部环境不可用，因此保留只读适配边界并明确标注模拟，不伪造连接。

## 成员 4：学生选课

- 建立/修改草稿，凑齐 4+2 后提交。
- 说明提交时才统一校验先修、容量、冲突，并用悲观锁避免超卖。
- 追问：修改已提交课表怎样处理容量？答：改回 DRAFT 并释放原占位，重新提交才占位。

## 成员 5：教师任课

- 选择 NET201、查看本人班级名单，再退选。
- 说明只允许本院系、无人任教、窗口开放且时间不冲突。
- 追问：为何名单不允许任意教师查？答：教学班所有权是独立于角色的第二层授权。

## 成员 6：成绩

- 在 2026-SPRING 已结束课程将成绩改为 B，切换学生查看 GPA。
- 说明仅 CLOSED 教学班可录入；I 不计 GPA，A-D 获得学分。
- 追问：空成绩是什么？答：暂未录入，不等同于 F，也不纳入成绩单统计。

## 成员 7：结算计费

- student1 提交后，以管理员关闭选课；展示 2 个无人教师班取消、3 张课表计费。
- 对一条计费先“模拟失败”，再“重试成功”。
- 追问：关选课顺序为什么重要？答：先取消无教师、再补位、再查最低人数，才能避免错误保留或取消。

## 彩排清单

- 答辩前执行 `docker compose down -v` 后重新 `docker compose up --build`，保证演示数据一致。
- 三个账号分别开浏览器无痕窗口，避免角色切换混乱。
- 先完成 student1 的 4+2 提交，再演示管理员关选课。
- 成员 5 的选择/退选演示应在管理员关选课之前。
- 每人准备一条失败场景，不只展示“点一下成功”。
