# 测试计划

自动化主路径位于 `backend/src/test/java/.../SevenModuleIntegrationTest.java`，每个模块一条端到端集成测试。下表同时列出人工异常用例，确保每人至少准备 5 条。

| 模块 | 正常用例 | 关键异常用例 |
|---|---|---|
| 1 认证 | 三角色正确登录；查询本人；退出 | 错误密码 401；无认证 401；学生访问管理员接口 403 |
| 2 人员 | 新增、查询、修改、删除；证件掩码 | 重复学号；缺姓名；非法状态；删除不存在 ID |
| 3 目录 | 查状态、课程、教学班；显示余量 | 不存在学期为空；无写接口；先修为空；教师为空正常显示 |
| 4 选课 | 建草稿、保存、修改、删除、4+2 提交 | 主/备选数量错；优先级重复；先修不满足；时间冲突；满员；窗口关闭 |
| 5 任课 | 查资格班、选择、名单、退选 | 跨院系；已有教师；时间冲突；查看他人名单；窗口关闭 |
| 6 成绩 | 查结课班、名单、录入 A-F/I、查 GPA | 非法成绩；非结课班；非本人教学班；名单外学生；空值保留 |
| 7 结算 | 关选课、取消、冻结、计费、失败重试 | 重复关闭；无教师；不足 3 人；草稿不计费；计费 ID 不存在 |

## 自动验证命令

```powershell
cd backend
mvn test

cd ../frontend
npm run build
npm audit --audit-level=high

cd ..
docker compose config --quiet
```

## 并发专项建议

正式报告可补一条 JMeter 场景：11 个不同学生同时提交同一容量为 10 的教学班。预期最多 10 条 ENROLLED，第 11 个收到“已满”提示，数据库不存在超额记录。当前核心代码已通过 `findByIdForUpdate` 为该场景提供串行容量保护。
